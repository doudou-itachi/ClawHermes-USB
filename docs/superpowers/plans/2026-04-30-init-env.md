# Init Env Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a safe `init-env` command that creates local env files from committed `.env.example` templates without overwriting existing secrets.

**Architecture:** Keep the behavior in the TypeScript core. The CLI exposes `init-env`, and the PowerShell dispatcher remains a thin pass-through that only whitelists the new action.

**Tech Stack:** TypeScript, Node.js, Windows PowerShell wrapper, Python `unittest` integration tests.

- [x] **Step 1: Write failing tests**

Add tests that run `init-env -Json` against a temporary USB root. Verify missing env files are copied from examples, existing env files are skipped, and `--dry-run` reports planned creation without writing files.

- [x] **Step 2: Implement TypeScript core behavior**

Add a helper that uses adapter-declared env files, copies from `.env.example` only when the target does not exist, and returns structured JSON.

- [x] **Step 3: Wire CLI and wrapper**

Expose `init-env` in the Node CLI and add it to the PowerShell dispatcher's allowed action set.

- [x] **Step 4: Verify and commit**

Run `npm test`, `git diff --check`, and the UTF-8 smoke check before committing the phase.
